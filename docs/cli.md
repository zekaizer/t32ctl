# t32ctl command-line contract

This is the Phase 1 contract of `t32ctl`: everything a caller can observe. It is the reference for
operators, who approve commands, and for maintainers, who add commands. The decisions behind the
contract are in [ADR 0002](adr/0002-phase1-cli-contract.md). Board profiles are in
[profiles.md](profiles.md), literal agent sessions in [cli-sessions.md](cli-sessions.md), and the
agent skill in [skills/t32ctl/SKILL.md](../skills/t32ctl/SKILL.md).

The binary implements the Phase 1 MVP: the commands whose PowerView behavior the Phase 0 probe
proved on build 168999, plus target memory and register reads. The generated tables list exactly
what the binary has. Everything else in this document is planned and marked so: it waits for a
target opt-in probe (`run-control`, `target-read`, `load-code`, `elf-unzip`) or for the lease and
the state file ([Planned commands](#planned-commands)).

Every call is one process. It connects to PowerView over RCL, acts, waits for the result, prints a
short report, and disconnects. Nothing runs in the background. What must survive between calls
lives in a state directory in WSL.

## Grades and permission rules

The first word after `t32ctl` is the permission grade. Every command lives under exactly one
grade, so a Claude Code rule on the first two words covers exactly that grade.

| Grade | What it may do to your PC and target | Default rule |
|---|---|---|
| `read` | Nothing. Reads target and debugger state; `read mem --to` writes a new file in t32ctl's output directory. | allow |
| `run` | Run control, breakpoints on code, on-chip watchpoints, symbol loading, the lease. The target runs; t32ctl writes no target data, and an exec breakpoint or a go target must be code. | allow |
| `write` | Writes target memory and registers, loads code, runs `write` procedures. | ask |
| `sys` | Board procedures the team rates above a memory write, such as DDR or clock setup. | ask |
| `burn` | Board procedures that write persistent storage (eMMC, NOR). Irreversible. | ask, never allow |
| `raw` | Arbitrary PRACTICE: typed text, any window, repository scripts. | ask, never allow |
| `admin` | Operator only: break a lease. | deny |

The grades form a total order: `read < run < write < sys < burn < raw`. `burn` sits above `sys`
because a reset cannot undo it. `raw` is the top because PRACTICE text can do anything, including
what `burn` does. `admin` is outside the order: it never acts on the debugger.

In the MVP, `run`, `write`, `sys`, and `burn` hold only board procedures (`<grade> proc`), and
`admin` has no command yet. The rules cover every grade already, so they do not change when a
planned command lands.

Generate the rules instead of typing them, so they always match the binary:

```sh
t32ctl read describe --format permissions
```

Merge the `permissions` member into `.claude/settings.json`. `never_allow` names the rules that
stay in `ask` when you relax others: during a rebuild loop you may move `write` or `sys` to
`allow`, and every flash and every raw command still asks. A test fails if a generated snippet
ever puts a `never_allow` rule in `allow`. The `deny` rules keep agents out of the operator's
command, the board profile directories and their scripts, the binding file, the connection
config, and t32ctl's state, so an agent's edit to any of them is refused; the operator edits
them by hand.

The rules are a convenience, not a security boundary. The firewall on port 20000 and your
approval are the boundary. The rules guard against an agent's mistakes and shortcuts, such as
editing a profile, appending a flag, or retrying; they do not stop a malicious agent. Three
properties keep the first word honest:

- Every leaf exists under exactly one grade, and no flag changes it.
- Flags come only after the grade word, and there are no aliases or abbreviations.
  `t32ctl --json read status`, `t32ctl r status`, `env X=1 t32ctl ...` and `./t32ctl ...` do not
  parse or do not match an allow rule, so they fall back to asking you.
- A leaf cannot do more than its grade. Its body receives a context typed by the grade, and the
  compiler refuses an operation above it (see [Inside a call](#inside-a-call)).

No flag bypasses a check. There is no `--force`, `--yes`, `--steal`, `--ignore-*`, `--no-*`,
`--skip-*`, `--unsafe`, `--override`, or `--verify` toggle, and a test fails if one appears.
`proc` flags are generated from the profile at run time, so profile validation rejects parameter
names that match the same pattern. The way past a refusal is a different command, and a different
command is a different rule.

Board procedures share one verb under every grade: `t32ctl <grade> proc NAME`. The grade word
must equal the grade the profile declares for the procedure; any other is exit 2 `grade-mismatch`
with the right command as `next:`. Phase 1 has no operator trust: a procedure runs at its declared
grade, and the memory map and the peripheral views are the profile as written.
[profiles.md](profiles.md#profile-changes) says what covers an edited profile until trust exists.

The operator's command, `t32ctl admin lease break`, will not be in the agent table, and the

### What the MVP commands print

Every connecting call prints the header first ([Output](#output)). The errors every connecting
call can end with are not repeated below: `profile-invalid`, `state-dir`, `unreachable`,
`no-answer`, `connection-lost`, `rcl-locked`, `cpu-mismatch` (all but `read status`), `pv-error`,
`interrupted`, and `usage` for any command line.

A profile is needed only where board knowledge is: `read mem` (the memory map), `read procs` and
procedures are exit 5 `no-profile` without one, before connecting. `read status`, `read reg`,
`raw eval`, `raw cmd` and `raw script` run from the connection config alone. They check no CPU
and print no notice about it: a missing profile is a standing condition, not an event, and
`read status` shows it.

`read status [--full]` reports the target against the profile, and PowerView. The CPU check never
refuses it: a mismatch is a notice, and the call exits 0 whenever PowerView answers, down or not.

<!-- transcript: mvp -->
```console
$ t32ctl read status
stopped core=0 pc=0x40083e10
target  acme_evb cpu=CortexA53 (matches profile) cores=4
profile boards/acme/acme_evb/support/t32ctl/
pv      build=168999 clients=1 practice=idle
[exit 0]
```

- `target`: the profile's `name`; `SYStem.CPU()` with `(matches profile)`,
  `(profile: <cpu>, mismatch)`, `(not checked while down)`, or `(no profile)`, which also drops
  the name; `cores=<CORE.NUMBER()>`, with `(profile: <n>)` when the profile says otherwise.
- `profile`: the profile directory, or `none: <why>` without a profile (`--full` then prints
  `profile none` in the `binding` line).
- `pv`: `build=<SOFTWARE.BUILD()>`; `clients=` from `RCL.TCP.NrUsedCons()`, else
  `api.RCL.TCP.NrUsedCons()`, else `?`; `practice=idle`, `running`, `dialog`, or `halted` (idle
  with a script on the stack), with `(depth <n>)` while the stack holds a script.
- `--full` adds `profile=<hash> (<n> files)` to the `profile` line, and the `binding`, `config`,
  and `state` lines ([profiles.md](profiles.md#binding-which-profile-and-which-elf) shows them).
- Planned: the `elf`, `stop`, `fault`, `bp`, and `lease` lines, and the run state of each core.

`read mem LOC [--len SIZE] [--width 1|2|4|8] [--to NAME]` reads memory that the profile's memory
map allows ([profiles.md](profiles.md#memory-map)).

- `LOC` is `[CLASS:]0x<hex>`, or `@<reg>` with an optional `+0x<hex>` or `-0x<hex>`. Symbol and
  source-line places are planned; today they are exit 2 `notation`.
- `--len` defaults to one cell, so a read of a device register touches no neighbor. It is at most
  `4K` without `--to`, and at most `[calls] transfer_max` (`1G` by default) with it.
- `--width` defaults to the width of the touched `mmio` regions, else the profile's `word`.
  `--len` must be a multiple of it.
- `--to NAME` writes the bytes into `~/.local/state/t32ctl/out/m-<4 hex>/NAME` instead, within
  `[calls] transfer_timeout`. The bound also covers the translation of the pages and the memory
  map check. A transfer its bound stops is exit 1 and leaves no file; stopped before the check,
  its `mem` line has no `phys=` and no regions, and `len=` and `width=` only as given.
- The `mem` line prints the address without its class when the class is the profile's
  `default_class`, the physical address after `phys=` for a translated class, and the regions the
  read touched. Cells print `0x` at the cell width, little-endian, 16 bytes per line.
- Exits: 2 `notation`, `memory-policy`, `refused`; 3 `target-down`, and `not-halted` while the
  target runs, for `@reg` or a touched region without `running = true`.

```console
$ t32ctl read mem @sp --len 64

mem 0x40107e40 len=64 width=8 class=D phys=0x40107e40 (region ram "ddr")
```

`read reg [NAME...]` reads registers of PowerView's selected core; without a name, the AArch64
general-purpose set `x0` to `x30`, `sp`, `pc`, and `cpsr`. A name is
`[A-Za-z][A-Za-z0-9_]{0,31}`, in any case, and prints as typed. Values print as `0x` and 16 hex
digits, four registers per line. Exits: 2 `notation`, `refused` (PowerView refused the named
register); 3 `target-down`, `not-halted`.

<!-- transcript: mvp -->
```console
$ t32ctl read reg x0 sp
stopped core=0 pc=0x40083e10
x0=0x0000000000000000 sp=0x0000000040107e40
[exit 0]
```

`raw cmd 'TEXT'` and `raw eval 'EXPR'` send one PRACTICE command or function literally
([Notation](#notation)). `raw eval` prints the value in argument notation and its type:
`TRUE()` or `FALSE()` (bool), decimal, `0x` hex, a decimal fraction (float), `1.5s` (time), the
text in double quotes (string), `(empty)`, or `<text> (type 0x<t>)` for a type t32ctl does not
interpret. `raw cmd` prints `cmd: done`, and a notice when a script is left on the PRACTICE stack:
a `DO` sent over RCL returns at once. Exits: 2 `notation`, `refused`; 3 `target-down` or
`not-halted`, only when PowerView answers with those status codes; 5 `no-answer` for a command
that blocks past the call budget ([Bounds](#bounds)).

<!-- transcript: mvp -->
```console
$ t32ctl raw eval 'OS.PTD()'
stopped core=0 pc=0x40083e10
"C:\Users\op\AppData\Local\Temp" (string)
[exit 0]
```

`<grade> proc NAME [--PARAM VALUE...]` runs a board procedure
([profiles.md](profiles.md#procedures)). `raw script ENTRY.cmm [--root DIR] [--timeout DUR]
[--out DIR] [-- ARG...]` runs a script set from the repository: the bundle is `--root`, by default
the directory of `ENTRY`, walked like a profile directory; `--out DIR` must not exist yet, and the
default output directory is `~/.local/state/t32ctl/out/s-<4 hex>/`. Both report what ran, how it
ended, and the files it wrote into `&t32ctl_out`:

| Result | Exit |
|---|---|
| `result: finished rc=0 after <d>[: "<msg>"]` | 0 |
| `result: finished after <d>[: "<msg>"]`: no rc, not a `burn` procedure | 0 |
| `result: finished without rc after <d>: a burn procedure must set &t32ctl_rc="0" after its verification` | 1 |
| `result: finished rc=<n or text> after <d>[: "<msg>"]` | 1 |
| `result: failed by a PRACTICE error after <d>`, then `message:`: the runner caught it | 1 |
| `result: halted by a PRACTICE error after <d>`, then `message:` and `line:`: the script was unwound | 1 |
| `result: timed out after <timeout>; the script was stopped and unwound` | 1 |
| `result: the upload of --<param> stopped at the <d> bound; the procedure did not run` | 1 |
| an exit-0 result with a declared output missing: `missing: <names>` | 1 |
| `error[dialog]`: the script opened a dialog; `error[script-vanished]`: the runner never reached its end | 5 |

The outputs line is `outputs: none`, or the output directory and one line per file
(`name  size`). Other exits: 2 `grade-mismatch`, `unknown-proc`, `proc-params` (`proc`), and
`bad-bundle`, `file-exists`, `notation` (`raw script`); 4 `pv-script-running`, `vm-busy`; 5
`pv-script-halted`, `residue`. [cli-sessions.md](cli-sessions.md) shows both.

### Bounds

Every wait is bounded by its type, and no setting removes a bound. A transfer (`read mem --to`,
and the upload of a procedure's file parameter) has a deadline of 10 min by default
(`[calls] transfer_timeout`), at most 1 h. `raw script --timeout` accepts 1 s to 2 h (5 min by
default), and so does a procedure's declared timeout. The skill keeps a single call under two
minutes unless the agent raised its own command timeout, and runs a longer call, such as a flash,
in the background.

Planned: `run go` and `run step` wait 30 s by default (the profile's `[timing]`), and `--wait`
accepts 100 ms to 10 min. `run lease take --wait` accepts at most 90 s. `write mem --from`,
`write load`, and `run symbols` are transfers under the same deadline.

`raw cmd` waits for its command. A command that blocks in PowerView, such as `WAIT`, holds the
call and keeps every other RCL client from connecting until it ends; past the RCL call budget the
call is exit 5 `no-answer`, and PowerView may still be running the command. Long work belongs in
`raw script`, whose script may `WAIT` while RCL keeps answering.

### Run control and breakpoints

Planned: this subsection waits on the `run-control` probe.

Run control acts on all cores, as TRACE32 SMP mode does. Every run command waits for the stop,
classifies it, and reports it, unless `--detach` says otherwise.

- `run go` without LOC on a running target only waits for the stop. A wait that times out is
  recorded like `--detach`, so a later stop is reported as a t32ctl stop, not as a change made
  outside t32ctl. `run go LOC` needs a halted target, and exit 3 `not-halted` says so.
- `run step out` reports the return value from the AArch64 return register, typed by the
  function's declared return type when the symbols know it (`ASSUMED(run-control)`).
- An exec breakpoint (`run bp set LOC`, `--on exec` by default) and a go target (`run go LOC`)
  must resolve inside a code section of the loaded ELF that lies in a `ram` or `rom` region.
  Anything else is exit 2 `not-code`, whose message suggests `--on write` for data. TRACE32 may
  implement an exec breakpoint in RAM by patching an instruction into memory
  (`ASSUMED(run-control)`), which is why the place must be code.
- Watchpoints (`--on write`, `read`, or `access`) use the core's on-chip debug units, so they
  never write target memory. A Cortex-A53 core has four, and a watchpoint that finds none free is
  exit 2 `no-hw-resource`. A watchpoint sees CPU accesses only; a DMA writer does not trigger it.
- A breakpoint's identity is its resolved address, kind, length, condition, and count. Setting
  the same identity again returns the existing tag, whatever `--tag` says. The same `--tag` with
  a different identity is exit 2 `tag-in-use`.
- `--count N` counts the hits where the condition is true (`ASSUMED(run-control)`). Setting the
  same breakpoint again does not reset the count.
- `run bp clear --all` clears every t32ctl-tagged breakpoint, other callers' included. Like every
  `run` command except `run lease take`, it is refused to a bystander under someone else's lease.

### Views for `read window`

Planned: this subsection waits on the `target-read` probe.

`read window VIEW` opens only views from a compiled table, plus the peripheral views the profile
declares. `t32ctl read window --list` prints both, without connecting. Any other window is
`t32ctl raw window 'TEXT'`, which asks.

| View | PowerView window | Argument |
|---|---|---|
| `list` | `List`: disassembly with source | `LOC`, checked against the memory map like `read mem`; default: the PC of the current core |
| `per.<name>` | `PER.view` of the section the profile names in `[per.<name>]` | none |

A peripheral view reads device registers, and some registers change state when read (a FIFO, a
clear-on-read status). The team therefore opts in per section in the profile.

```console
$ t32ctl read window --list
view        shows                                          argument
list        disassembly and source around a location      LOC (default: the pc)
per.clocks  PER.view section "Clock Controller" (profile)  -
per.gicd    PER.view section "GIC Distributor" (profile)   -
[exit 0]
```

## Notation

One grammar for every argument that names a place, parsed once at the boundary:

| Form | Example | Meaning | Status |
|---|---|---|---|
| hex address | `0x40080a98` | `0x` is required; a bare number is never an address | MVP |
| access class | `A:0x40000000` | one of the profile's `classes` (default `A`, `D`, `P`) before `:`; without one, the profile's `default_class`; any other class is `raw` | MVP |
| register-relative | `@sp`, `@x1+0x10`, `@x1-0x8` | the register's current value, optional `0x` offset | MVP |
| symbol | `worker_loop`, `worker_loop+0x84` | C identifier, optional `+` offset | planned (`elf-unzip`) |
| source line | `src/worker.c:61` | any path suffix that names one loaded source file, then the line | planned (`elf-unzip`) |

The left side of `:` is a source file when it contains `.` or `/`, otherwise an access class.
Until source lines land, such a place is exit 2 `notation`, and so is a symbol. Memory regions are
physical, so a place in a translated class is checked after translation
([profiles.md](profiles.md#memory-map)).

Every value t32ctl prints is in these forms, so any printed token can be pasted as an argument:
places (`pc=0x40080a98`), sizes, durations, and values. Every notation type parses what it
prints: `parse(display(x)) == x` is a test for each one. Planned with symbols: places print with
`sym=worker_loop+0x84 src=src/worker.c:61` as well.

Other arguments:

- **Values:** `0x` hex, plain decimal (`42`, `-1`), decimal fraction for floats (`1.5`), or an
  enum member name for enum variables. PRACTICE reads a bare number as hex; t32ctl never sends
  one: an integer parameter reaches a script as `42.`.
- **Sizes:** bytes in decimal (`24`), `0x` hex, or a `K`, `M`, `G` suffix (`4K`, `64M`). The
  suffixes mean KiB, MiB, and GiB, on input and on output.
- **Durations:** `500ms`, `30s`, `41.3s`, `5m`, `2m40s`, `1h`, `1h30m`. Decimal seconds are
  accepted. Each duration has its range in its type; a value outside it is a `notation` error,
  never clamped.
- **Register names (`NAME`, for `read reg` and `@reg`):** a letter, then at most 31 letters,
  digits, or `_`, in any case: `x0`, `sp`, `esr_el1`.
- **Procedure parameters:** `--<name> VALUE`, generated from the profile at run time, where a
  parameter `foo_bar` is typed `--foo-bar`; booleans are `true` or `false`. The types are in
  [profiles.md](profiles.md#parameters).
- **PRACTICE text (`raw cmd 'TEXT'`, `raw eval 'EXPR'`):** one line without control characters,
  1 to 2037 bytes (the RCL command limit), quoted whole in single quotes: unquoted, the shell
  takes `<`, `>`, `|`, `&`, `;` and, in zsh, `(` `)` itself, and a stray `<...>` placeholder ends
  in a shell parse error before t32ctl runs. It is sent literally:
  PowerView expands no macro in a command sent over RCL, so `&name` stays literal, and a
  function's file argument is a literal name, not an expression.
- **Script arguments (`raw script ... -- ARG...`):** letters, digits, and `_ - . / : + = , @`,
  at most 4 KiB in total (the PRACTICE macro limit).
- **Output names (`NAME`, for `--to`):** a plain file name, without `/` and not starting with `.`.
  The file is written as `~/.local/state/t32ctl/out/<run-id>/NAME`, and the report prints its
  path.

Planned arguments:

- **Cores and frames:** `0`-based numbers, as printed after `core=` and at the start of a
  `read stack` line.
- **Breakpoint tags:** `b1`, `b2`, ... assigned by t32ctl and never reused, or your own label
  (`[a-z][a-z0-9_-]{0,15}`, not of the form `b<number>`).
- **Expressions (`EXPR` of `read var` and `write var`):** an lvalue in C syntax, quoted in single
  quotes (`'item->state'`): identifiers, `.`, `->`, `[integer]`, unary `*` on a typed pointer
  lvalue, and `&` of an lvalue (`'&g_cfg.mode'`). t32ctl renders `&` so PRACTICE never reads
  `&name` as a macro. Casts of integers to pointers, function calls, assignments, and other
  operators are exit 2 `notation`. The address and size of the lvalue are checked against the
  memory map.
- **Conditions (`COND`, for `--if`):** `lvalue OP constant`, with OP one of `==`, `!=`, `<`,
  `<=`, `>`, `>=`, joined by `&&` and `||` (`'item == 0'`, `'item->state == 2 && n > 4'`). TRACE32
  evaluates a condition at each hit, so a pointer it dereferences is not checked against the
  memory map. That is a known limit.
- **Lease tokens:** `tk-` and 16 lowercase hex digits (64 bits), as printed by `run lease take`.
- **Views:** `list` or `per.<name>`, as `read window --list` prints them.

## Output

Text by default; `--json` prints one object with the same content. Everything goes to stdout;
stderr carries only a panic.

```text
stopped core=0 pc=0x40083e10                         <- header, connecting calls only
! cleaned up after an interrupted call: 2 steps      <- notices, if any
<body lines>                                         <- per command
error[<tag>]: <message>                              <- on failure
  <detail lines>
next: <command>                                      <- 0 to 2 hints
```

- The header is one line, read after the body: the run state and where the target is.
  `stopped core=<n> pc=<0x...>` names PowerView's selected core (`CORE()`) and its PC;
  `running cores=0-3` counts the cores (`CORE.NUMBER()`); `down` means the debug port is down.
  The header is best effort: a value PowerView refuses is left out, and a failed read never fails
  the call.
- Planned for the header: the epoch `e<n>` before the run state
  ([State](#state-kept-between-calls)), `sym=` and `src=` after the PC, the state `mixed`,
  `lease=<id>:you` (with `,contended` while another caller waits for it) or `lease=<id>:other`,
  and `elf=stale` when the build's ELF differs from the loaded one.
- Calls that do not connect print no header: parse errors, `read describe`, `read procs`, and every
  error found before connecting, such as `profile-invalid`, `notation`, or `grade-mismatch`.
- Printed values are arguments. Memory cells print `0x`-prefixed at the cell width
  (`0x0000000040107e60`). A size prints with the largest of `K`, `M`, `G` that divides it, else in
  bytes (`24`, `4K`, `2411724`). A duration prints in milliseconds below 1 s (`840ms`); below
  1 min in seconds, with one decimal unless it is whole (`41s`, `41.3s`); from 1 min in hours,
  minutes, and whole seconds, without zero parts (`2m40s`, `45m`, `2h`). A measured duration is
  rounded to that precision before it is printed. Planned with `read var`: a typed value prints
  signed when its type is signed (`-22 (int)`), an enum as its member and number
  (`MODE_IDLE (0)`), and a pointer in `0x` hex.
- A body is bounded: `read mem` prints at most `4K` as text, and larger reads use `--to`. No MVP
  body is cut. Planned: `read stack` lists 16 frames, and windows print 40 lines unless `--limit`
  says otherwise; a cut body ends with `... <n> more lines` and a `next:` line that prints the
  rest, for example `next: t32ctl read window per.gicd --skip 40`.
- An outcome other than the one asked for (exit 1) is a result, not an error: the body says what
  happened and there is no `error[...]` line.

### Notices

A notice reports something the caller did not ask for but must not miss. In the MVP every notice
comes from the call that prints it:

| Notice | Example |
|---|---|
| Journals replayed at connect | `! cleaned up after an interrupted call: 2 steps` |
| Residue, after a replay or this call | `! residue: unwind PRACTICE stack; in PowerView type: END (END also closes every dialog and OPEN file)` |
| Cleanup kept under this call's own script, which could not be unwound | `! cleanup under the script t32ctl started (2 steps): deferred: kept until the PRACTICE stack is empty; a later call cleans up after it` |
| Replay deferred: an interrupted call's script may still run | `! cleanup left by an earlier run: deferred: its script may still be running (practice=running, depth 1); a later call cleans up after it` |
| Replay deferred: an interrupted call's script has halted, or waits in a dialog | `! cleanup left by an earlier run: deferred: its script has halted (practice=halted, depth 1); a later call cleans up after it once the stack is empty`, then `! residue: unwind PRACTICE stack (left by an earlier run): only if the halted script is t32ctl's; in PowerView type: END (END also closes every dialog and OPEN file)` |
| CPU mismatch (only `read status`; every other command refuses) | `! connected CPU CortexA72 is not the profile's CortexA53: every other command refuses` |
| A script left on the stack by `raw cmd` | `! a PRACTICE script is on the stack after this command (depth 1, running); proc and raw script calls wait for it` |

A residue notice names one PowerView command per line, for what cleanup could not undo. A step
cleanup did not attempt keeps why before its command, the condition for typing it:
`! residue: break target (left by an earlier run): only if t32ctl left the target running; in
PowerView type: Break`. A deferred replay names nothing to type while the script may still run:
the next call that finds PowerView idle with an empty PRACTICE stack replays the journal. A halted
script, or one in a dialog, never ends by itself: the deferral also names `END`, for a human to
type only if that script is t32ctl's. Neither does cleanup kept under
a script this call could not unwind: the call's `residue` error names `END`, and the next call
after it replays the journal.

Planned with the state file: notices that stay until a call acknowledges them. Every call prints
the notices not yet acknowledged, and a call allowed to acknowledge a notice is the last to print
it. While a lease is held, only the holder acknowledges, and only the holder sees the contended
notice.

| Planned notice | Example |
|---|---|
| Change made outside t32ctl | `! e20->e21 changed outside t32ctl: the target ran and stopped at pc=0x40085c40 (cause unknown)` |
| Stop after `--detach` or a timed-out wait | `! e7->e8 since the last call: the target stopped (breakpoint b1 on core 2)` |
| Interrupted call | `! e41->e42 by an interrupted call (run go --wait 1m30s at 10:02:11, pid 4242): it resumed the target` |
| Incomplete flash | `! burn proc flash --part user did not complete (11:03:12, e41): the storage may hold a partial image` |
| Lease contended (holder only) | `! another caller has been waiting for the lease since 10:15:40, until 10:17:10 at the latest` |
| Instance marker missing | `! PowerView instance marker missing: restarted, or PMACRO.RESet ran` |
| Breakpoint missing | `! breakpoint b3 is no longer in PowerView (removed in the GUI?); tag dropped` |

Only a `read` or `run` call will acknowledge a change made outside t32ctl. A `write`, `sys`,
`burn` or `raw` command that finds one prints the notice and refuses without acknowledging it, so a
blind retry is refused again.

An incomplete flash is never acknowledged: it is repeated on every call until a procedure with
the `flash` effect completes.

A missing instance marker means that PowerView restarted or that a script ran `PMACRO.RESet`,
which deletes every global macro. t32ctl cannot tell which, so it reports a change of unknown
cause, sets the marker again, and keeps the breakpoint tags and the ELF record. The breakpoint
check on the same call drops any tag PowerView no longer has.

### Hints

`next:` lines are complete commands chosen from the state the command left behind. A caller that
ignores them loses nothing but a hint. A hint is the words of a command line, quoted for the shell
where a word needs it. A test renders every hint the table can produce and parses it back, so a
renamed command fails the test, not the caller.

A hint is never a template. When the natural next step needs a value only the caller knows, such
as the purpose of a lease, the hint is omitted and the message says it in prose.

| After | Hints |
|---|---|
| `grade-mismatch` | the same procedure call under its declared grade, with the caller's parameters and `--build` |
| `target-down` | `t32ctl <grade> proc attach` with the caller's `--build`, when the profile declares `attach` without a required parameter |

Planned hints, with the commands they name; when the caller passed a valid `--lease` token, every
hint will carry it, so the holder can paste a hint as is:

| After | Hints |
|---|---|
| A stop: breakpoint, watchpoint, reached, halted, external, unknown | `read stack` |
| A step | none |
| A wait that ended with the target still running (exit 1) | two alternatives: `run halt`; `run go --wait <the same wait>` |
| `run go --detach` | none |
| `read stack` while a fault frame is known and not shown | `read stack --frame <fault frame>` |
| `run bp set`, also when the breakpoint was already set | `run go` |
| `read status` with `elf=stale` | `run symbols`; loading code with `write load` is the caller's own decision |
| `changed-externally` (exit 3) | the read the refused write was based on (`write var X` gives `read var X`, `write mem LOC` gives `read mem LOC`, `write reg R` gives `read reg R`), else `read status` |
| `not-halted` | `run halt` |
| `no-symbols` | `run symbols` |
| `not-code` | none; the message suggests `--on write` for data |
| `lease-held`, `lease-required`, `lease-ended` | none; the message says how to take a lease |
| A cut body | the same command with `--skip` |

Reads of data produce no other hints: the caller knows what it wants next better than a table.

### JSON

`--json` prints one object, schema `t32ctl.report/1`. Members: `schema`, `command`, `exit`
(`code` and `class`), `header` (`null` for a call that did not connect), `notices`, `body` (tagged
by `kind`), `truncated` (always `null` in the MVP), `error` (`kind`, `message`, `details`), and
`next`. Addresses are strings in argument notation (`"0x40080a98"`), so 64-bit values survive
every JSON consumer. Adding a member is compatible; renaming or removing one bumps the schema
number. The members of planned features (`header.epoch`, `header.lease`, `header.elf_stale`,
`at.sym`, `at.src`, `error.retry_after`, `error.at`) are absent, not `null`, so adding them later
is compatible. The text and the JSON are two renderings of one report value, so they cannot
disagree.

```json
{"schema":"t32ctl.report/1","command":"read reg","exit":{"code":0,"class":"ok"},
 "header":{"run":"stopped","core":0,"at":{"pc":"0x40083e10"}},"notices":[],
 "body":{"kind":"regs","core":0,"regs":[{"name":"x0","value":"0x0000000000000000"},
   {"name":"sp","value":"0x0000000040107e40"}]},"truncated":null,"error":null,"next":[]}
```

`t32ctl read describe` prints the static schema as JSON, schema `t32ctl.describe/1`: the grades
with their rule, never-allow mark, and order; every command with its path, usage, wait, whether
it connects, examples, and arguments; the global flags; the notation forms; the exit codes; and
the error tags. It holds no target data. Board procedures and state come from
`read procs --json` and `read status --json`.

Errors are classified in one module, by RCL status code, `RemoteKind`, `StageError` variant, and
runner outcome, never by message text. Exit 2 means the command text is wrong. Exit 3 means the
target is not in the state the command needs: the debug port is down (`target-down`) or the
target runs (`not-halted`); the report names what to do before running the same command again.
A finished script or procedure is a result: rc 0 is exit 0; a
non-zero rc, a PRACTICE error, or a timeout is exit 1. The script assigns its rc as a string,
`&t32ctl_rc="0"`; t32ctl takes `0`, `0.` and `0x0` as zero, and any other value, numeric or not, is
a failure. An empty rc is success except for a `burn` procedure. A dialog is exit 5, because only
the operator can close a PowerView window. A run whose runner never reached its end
(`RunOutcome::Vanished`: idle, empty stack, no token) is exit 5 `script-vanished`, because
something outside t32ctl cleared the PRACTICE stack.

## State kept between calls

In the MVP, t32ctl keeps no state of its own between calls. Two directories hold what `t32stage`
and the output files need:

| Path | Holds |
|---|---|
| `~/.local/state/t32ctl/pv/<host>-<port>/` | the t32stage journal and the `VM:` lease (`vm-*.lock`): this directory is the stage's state directory |
| `~/.local/state/t32ctl/out/<run-id>/` | output files of scripts (`s-`), procedures (`p-`), and `read mem --to` (`m-`); a run id is its prefix and 4 hex digits |

`<host>` and `<port>` are the endpoint as configured, so `host = "auto"` is always
`pv/auto-20000/`, whatever address it resolves to. t32probe keys its default state directory by
the same rule, so both tools share the `VM:` lock and replay each other's journals
([architecture.md](architecture.md#t32ctl-the-phase-1-contract)). `$XDG_STATE_HOME` replaces
`~/.local/state` when set. Nothing removes old output directories yet.

- **Exclusion.** The MVP serves one caller per PowerView, with its background calls. Two staged
  calls (procedures, `raw script`) cannot share the `VM:` window (exit 4 `vm-busy`), and a run
  starts only on an empty PRACTICE stack (exit 4 `pv-script-running`, or exit 5
  `pv-script-halted` for a halted script that the call did not start). Reads take no lock.
- **Interrupted calls.** A call journals every PowerView side effect before it makes it and
  cleans up after itself, also after Ctrl-C. The next call on the same PowerView replays the
  journal of a call that died, and its notices say what it cleaned up and what it could not. A
  call that died while its script ran (a flash after `kill -9`) may leave that script running:
  until PowerView is idle with an empty PRACTICE stack, replay leaves its journal alone, since
  the script may still write under the files and macros it names. A replay never types `END`. A
  call that cannot unwind its own script leaves the cleanup under it journaled the same way.
- **Current core.** Commands look at PowerView's selected core (`CORE()`), which the header
  prints. No command selects a core, so parallel callers cannot move it under each other.
- **An interrupted `burn`.** Its report says that the storage may hold a partial image. No record
  outlives the call, so no later call repeats the warning.
- **No epoch.** A change made outside t32ctl, in the GUI or by another tool, goes unnoticed. Run
  `read status` right before a command that asks your human.

### Planned: the state file

The epoch, the breakpoint tags, the loaded ELF, intents, flash progress, and the lease need a
state file and three locks in the per-PowerView directory:

| Path | Holds |
|---|---|
| `~/.local/state/t32ctl/pv/<host>-<port>/state.json` | epoch, last fingerprint, unacknowledged change, last stop, loaded ELF, breakpoint tags, intents, flash progress, the lease and the previous lease |
| `~/.local/state/t32ctl/pv/<host>-<port>/state.lock` | the `flock` around each read-modify-write of `state.json` |
| `~/.local/state/t32ctl/pv/<host>-<port>/call.lock` | the target-exclusion `flock`; its text is the holder's pid, command, start, and bound |
| `~/.local/state/t32ctl/pv/<host>-<port>/inflight/<pid>.lock` | one liveness `flock` per live call |

`state.json` is replaced atomically by rename, so a crash leaves the previous version.

- **Epoch.** Every change of the target that t32ctl sees bumps `e<n>`: its own runs, steps,
  writes, code loads, and procedures that touch the target, and changes made elsewhere (the
  PowerView GUI, another tool, the target stopping on its own). A `write`, `sys`, `burn` or `raw`
  command always bumps it, because it may have changed memory the fingerprint does not cover.
  The fingerprint is five cheap RCL reads: an instance marker (a global macro t32ctl sets), the
  debug port, the run state, the selected core and its PC, and the PRACTICE stack depth.
- **Changes made elsewhere.** A change t32ctl did not make is reported as a `!` notice, and only a
  `read` or `run` call acknowledges it. A `write`, `sys`, `burn` or `raw` command that finds an
  unacknowledged change refuses with exit 3 `changed-externally` and does nothing; a blind retry
  is refused again. While a lease is held, only the holder acknowledges. Without a lease, the
  guard protects one caller: another caller's read acknowledges the change for everyone. Callers
  that share the debugger therefore take a lease before a write sequence.
- **Current core and frame.** The current core is the core of the last stop; commands without
  `--core` look at it. The frame defaults to 0. Both are derived, never set: no command stores a
  selection, so parallel agents cannot move it under each other. `--core` and `--frame` are per
  call.
- **Breakpoint tags.** `b1`, `b2`, ... or your `--tag`, one per breakpoint identity
  ([above](#run-control-and-breakpoints)). Tags are never reused. PowerView has no function that
  lists breakpoints, so the tag list is the source of truth, checked against PowerView by address
  on every call; a breakpoint removed in the GUI is reported once and dropped.
- **Loaded ELF.** Path, hash, mode (code and symbols, or symbols only), and the epoch of the load.
  The build file's size and mtime decide when to rehash it.
- **Intent.** Before a mutating step (a run, a step, a breakpoint change, a write, a load, a
  procedure, a script), the call records what it is about to do, its pid, and its epoch, and
  clears the record when the step completes. An intent belongs to a dead call exactly when that
  call's `inflight/<pid>.lock` can be taken; a run wait that is still polling holds its lock, so
  its intent is never taken for a dead one. The next call attributes a dead call's change to it,
  reports it once as an interrupted call, and does not refuse writes as if the GUI had changed the
  target. It never redoes or undoes the dead call's action. A breakpoint entry written before
  `Break.Set` is confirmed or dropped the same way.
- **Flash progress.** A procedure with the `flash` effect is recorded before it starts and cleared
  only when it completes with rc 0, which the script sets explicitly (`&t32ctl_rc="0"`,
  [profiles.md](profiles.md#parameters)). Otherwise the record stays, and every call reports it
  until a flash completes.
- **Lease.** Holder id, purpose, deadlines, the pid of a holder call in flight, a waiter's
  deadline while one waits, and the previous lease for the next `run lease take` to report. The
  token is stored only as a SHA-256 hash.

Three locks, one job each:

| Lock | Held by | Job |
|---|---|---|
| `inflight/<pid>.lock` | every call, for its whole life | Liveness only: a call is dead exactly when its lock can be taken. |
| `state.lock` | every call, `read status` included, briefly around each read-modify-write of `state.json` | Consistency of `state.json`. |
| `call.lock` | every call that connects, except `read status`; a run wait and a lease wait release it while they poll | Target exclusion: a core select and its restore, a set and its check, a lease check and the action it admits. |

A call that cannot get `call.lock` within the lock wait (10 s by default) gets exit 4
`call-busy`. `read status` never waits for it. When another call holds it, `read status` reports
that call from the lock's text and the rest from the state file, and skips the fingerprint.

## The lease

Planned: the MVP has no lease, no `--lease` flag, and no `admin` command. Until the lease lands,
the MVP serves one caller per PowerView ([State kept between calls](#state-kept-between-calls)).

Several agents may share one PowerView: parallel Claude Code sessions, a parent agent and its
subagents, or an agent and the operator in the GUI. An agent that must keep the target still
across calls, for example while it inspects a target halted at a breakpoint, takes a lease. Other
callers may still run short reads and wait for the lease; anything else gets exit 4 with who holds
it, why, and until when.

| Question | Decision |
|---|---|
| Opt-in | No lease held: no token, no extra call, no flag, no cost. |
| Holder gets | Exclusive run control, writes, procedures, staged transfers, and raw. |
| Others get | Short reads: every `read` leaf except `read proc` and `read mem --to`. Besides those, only `run lease take`, which waits for the lease with `--wait` or is refused with exit 4. |
| Idle timeout | 10 min by default; the operator may set 1 to 30 min. Every call carrying the token renews it; there is no renew command. |
| Absolute cap | 30 min by default; `--for` from 5 min up to the operator's maximum, never above 2 h. Fixed at take; renewal never moves it. |
| Holder call in flight | Pins the lease while the call is alive, which its `inflight` lock proves. A killed holder's pin ends at once. Every call has its own bound, so the pin is bounded too. |
| Expiry without cooperation | Evaluated lazily by whoever reads the state file next. Nothing runs at expiry. |
| Target at expiry | Left as is (halted at a breakpoint, or running). The next taker is told how the previous lease ended, where the target is, and which tags were set under it. |
| Identity | `--lease tk-` and 16 hex digits, printed once by `run lease take`, stored only as a SHA-256 hash. |
| Forgotten token | The caller is a bystander: short reads and `run lease take` pass, everything else gets exit 4 naming the lease. Fails closed. |
| Subagents | Bystanders, unless the parent passes them the token in their prompt. |
| What others see | Id, purpose, idle and cap deadlines, time since the holder's last call, and exit 4 (`retry_after` in JSON). |
| Contended | Set only by a polling `run lease take --wait`, stored with that waiter's deadline (at most 90 s), and cleared at the deadline. The holder's header shows `contended` while it is set. |
| Waiting | No queue. `run lease take --wait` polls outside `call.lock` for at most 90 s, which fits one agent command. |
| Ended lease | Never comes back. While it is the previous lease, its token gets exit 3 `lease-ended`; an older token gets exit 2 `unknown-lease`. The holder takes a new lease, which reports how the previous one ended. |
| Where it lives | `state.json` of the per-PowerView directory, under `state.lock`. Atomic and free of round trips; a t32ctl in another WSL instance does not see it. |
| Operator break | `t32ctl admin lease break --reason TEXT`, with y/N. It ends the lease at once. A holder call in flight finishes under `call.lock`, so others get `call-busy` until it does. |

Every bound is a `Bounded<MIN, MAX>` type: idle 1 to 30 min, cap 5 min to 2 h, take wait 0 to
90 s, run wait 100 ms to 10 min, transfer 1 s to 1 h, procedure and script timeout 1 s to 2 h. No
value means "forever", and no flag or setting removes a bound.

Rules, all pure functions of the state file, the live `inflight` locks, and the clock:

1. No lease held: every caller is admitted and nobody passes a token.
2. Held: the caller whose token hashes to the holder's is the holder. Anybody else may run short
   reads and `run lease take`, nothing else. A refusal is exit 4 `lease-held`. It has no `next:`
   line, because taking the lease needs a purpose only the caller knows; the message says to take
   the lease with a purpose and `--wait` instead.
3. A lease ends at the first of: release, operator break, last call plus idle, and the cap. Idle
   and cap expiry wait while a holder call is alive; operator break does not.
4. `run lease take` by the current holder (with its token) renews the idle timeout and keeps the
   cap. A polling `run lease take --wait` marks the lease contended until its own deadline; a
   refused call does not.
5. A token of the previous lease gets exit 3 `lease-ended`. A token that matches neither the
   current nor the previous lease gets exit 2 `unknown-lease`.

Composition: the lease decides who is admitted, `call.lock` keeps one call at a time on the
target, `state.lock` keeps `state.json` consistent, and the epoch still reports changes made
outside t32ctl (the GUI) to the holder. `VmLease` stays an internal detail of one staged call.

The operator ends a lease by hand:

```console
$ t32ctl admin lease break --reason "taking over in the GUI"
lease L7f3e "step through worker_loop crash", taken 10:14:12, last call 38s ago
  ends by 10:44:12 at the latest
Break it? [y/N] y
lease L7f3e broken; its holder's next call gets: taking over in the GUI
[exit 0]
```

## Higher-level commands

Most leaves are single debugger actions. These compose more, and each has a reason it cannot be a
sequence of primitives. In the MVP, `read mem --to`, `raw script`, and `<grade> proc` (without the
lease check) exist; the others are planned.

| Command | Why it is not a composition |
|---|---|
| `run go LOC`, `run step` | Start, bounded client poll, stop classification, fault registers, and the return value after `step out`. A run that does not wait is the most common agent mistake, and a PRACTICE `WAIT` sent over RCL keeps every other RCL client out until it ends. |
| `read stack` | One `Frame.view` window parse gives frames, args, and locals without moving PowerView's view. A `Frame.Up` loop moves the GUI's view and costs a round trip per frame. |
| `write load`, `run symbols` | The ELF goes through `VM:` staging: gzip, `/UNZIP` detection and its fallback, window sizing, the hash record. Composing would expose staging. |
| `read mem --to`, `write mem --from` | Large transfers switch to staged `Data.SAVE.Binary` and `Data.LOAD.Binary` in slices; the agent sees one command. |
| `raw script` | Bundle (always gzipped), snapshot cache, runner token protocol, dialog handling, unwind, output collection. Unsafe to sequence by hand. |
| `<grade> proc NAME` | The script machinery plus typed parameters as macros, file parameters uploaded in slices, the grade and lease checks, and the outputs check. |
| `run lease take --wait` | A bounded wait for a free lease. The alternative is a retry loop in the agent. |

Flashing is not a built-in command. The controller setup is board-specific, so an eMMC flash is a
`burn` procedure in the board profile; [profiles.md](profiles.md#flashing-an-emmc) shows one.

## Inside a call

This section is for maintainers. One call runs this pipeline, and every guarantee in it lives in
one place:

```text
argv -> Cli::try_parse_from ----------------------------------------- usage: exit 2
     -> read describe: print, exit 0
     -> resolve config, binding, profile and variant; hash ---------- profile-invalid: exit 5
     -> no profile: read mem, read procs, proc ----------------------- no-profile: exit 5
     -> read procs: print, exit
     -> checks without PowerView: notation, grade and parameters,
        files, --out, the bundle; the output directory --------------- exit 2
     -> state directory pv/<host>-<port>/ --------------------------- state-dir: exit 5
     -> connect (host auto: each candidate in order) ---------------- unreachable, no-answer: exit 5
     -> replay this PowerView's t32stage journals ------------------- notices
     -> T32_GetState; CPU check unless down, debugger-config, or ---- cpu-mismatch: exit 5
        no profile
     -> the leaf body with its Ctx<G> ------------------------------- body, exit 0 or 1, or an error
     -> cleanup: close the stage under a fresh 30 s deadline -------- residue: exit 5
     -> header (best effort) -> report -> text or JSON -> exit code
```

The CPU check is skipped while the debug port is down and for procedures that declare the
`debugger-config` effect, so an `attach` procedure can select the CPU. `read status` reports a
mismatch instead of refusing.

SIGINT, SIGTERM and SIGHUP (a closed terminal) set a flag that reaches the session through
`t32rcl`'s `Cancel`. The first one cancels the call in flight, runs cleanup under a fresh 30 s
deadline that the flag does not cancel, reports `error[interrupted]` with what was cleaned up, and
exits 130. A second one exits at once. A SIGHUP the caller ignored (`nohup`) stays ignored.

Planned between these steps: `inflight/<pid>.lock` and `call.lock` after the profile; the lease
check under `state.lock`; the dead calls' intents and the fingerprint after connecting; the
refusal of a `write` and above after an unacknowledged outside change; recording the stop, tags,
and epoch in `state.json` after the body; and, for a run leaf, no `Break` on Ctrl-C.

### A leaf cannot exceed its grade

A leaf under grade `G` receives a `Ctx<G>`. The debugger operations live in impl blocks bounded
by grade, so a leaf can call only what its grade allows, and the compiler checks it:

| Impl block | Operations | Status |
|---|---|---|
| `impl<G: Grade> Ctx<G>` | Status; read registers; resolve a place and read memory, checked against the memory map; `run_procedure` with a `ProcPrep<G>` built from an `Admitted<G>` proof | MVP |
| `impl Ctx<Raw>` | PRACTICE text: a command, a function, a repository script | MVP |
| `impl<G: Grade> Ctx<G>` | Read the stack, variables, symbols, breakpoints; text of a table view | planned |
| `impl<G: AtLeast<Run>> Ctx<G>` | Go, step, halt, wait for a stop, set and clear breakpoints, load symbols, take and release the lease | planned |
| `impl<G: AtLeast<Write>> Ctx<G>` | Write memory, registers, and variables; load code | planned |
| `Ctx<Sys>`, `Ctx<Burn>` | Nothing new beyond procedures at their own grade | MVP |
| `impl Ctx<Raw>` | Any window | planned |

`AtLeast<F>` will be implemented for every grade at or above `F` in the order
`read < run < write < sys < burn < raw`, so `Ctx<Raw>` can do everything; no MVP operation needs
a grade range. Compile-fail tests show that `Ctx<Read>` has no `cmd` and `Ctx<Burn>` no `eval`.
`Admitted<G>` is built only by the grade check, which compares the grade word with
`effective_grade`. `run_procedure` takes only a `ProcPrep<G>`, which `procs::prepare` builds from
the `Admitted<G>` it consumes, and derives from `G` whether the run is a burn, so no leaf runs a
procedure without the check; compile-fail tests show that no other code can build either one. The
`t32rcl` `Session` and the `t32stage` `Stage` are private to `Ctx`; no leaf reaches them. Every
PRACTICE text comes from builders in `t32stage::practice`, as
[architecture.md](architecture.md#t32ctl-the-phase-1-contract) records.

### Policy hooks

Two functions in the `policy` module decide what a profile allows:

- `effective_grade(&Profile, &str) -> Option<GradeId>`: the grade a procedure runs at, which the
  grade word must equal; `None` for a name the profile does not declare.
- `effective_memory(&Profile) -> MemoryPolicy`: the memory map, the accepted access classes, the
  default class, and the default cell width (`word`) of the selected variant. The peripheral views
  join it with `read window`.

In Phase 1 both return what the profile declares. They are the single hook a later trust layer
replaces: no other code reads a declared grade, the memory map, or the views from the profile.
The profile hash is computed on every call and printed as `profile=<hash>` by `read procs` and
`read status --full`, so a later trust record has a key to compare.

### One definition

The clap derive is the only list of commands. Each leaf's argument struct carries its spec
through the `leaf!` macro: its grade and path, what it waits for, whether it connects, its
examples, and for `proc` the usage tail. Planned leaves add their effects, lock use, and whether a
bystander under someone else's lease may run them. Dispatch requires the `Leaf` trait, which only
that macro implements, so a leaf without a spec does not compile. From that definition come
`--help`, `t32ctl read describe`, the generated blocks in this file and in the skill, and the
permission snippet. `GradeId` holds the policy that follows from the grade (default rule,
never-allow, order), `Exit` holds the exit codes and their next actions, and `ErrorKind` holds the
error tags. `proc` flags are outside this definition: they are
generated from the profile at run time.

Tests that keep it one definition:

- Every example in every leaf spec parses to its own leaf.
- Every `$ t32ctl`, `A$ t32ctl`, `B$ t32ctl` and `next:` line in this file,
  [profiles.md](profiles.md), [cli-sessions.md](cli-sessions.md) and the skill parses, or the
  command it names is in the [planned table](#planned-commands).
- The planned table is disjoint from the binary: no planned command, flag, place form, or tag
  exists in it.
- Nothing parses before the grade word, and no alias or abbreviation exists.
- No flag or alias matches the bypass pattern: `force`, `yes`, `steal`, `ignore*`, `no-*`,
  `skip*`, `unsafe`, `override`, or a `verify` toggle. Profile validation applies the same
  pattern to procedure parameters.
- Every hint the table can produce renders and parses back to the same arguments.
- The generated blocks in this file and in the skill equal the output of `t32ctl read describe`.
- No `never_allow` rule appears in the snippet's `allow`.
- `Ctx<Read>` has no `cmd`, `Ctx<Burn>` no `eval`, only the grade check builds an `Admitted<G>`, and
  only `procs::prepare` a `ProcPrep<G>`, checked with compile-fail tests. Planned: `AtLeast` matches
  the grade order.
- The example config, binding file, and profile in [profiles.md](profiles.md) load and validate.
- The transcripts marked `transcript: mvp` in this file, [profiles.md](profiles.md), and
  [cli-sessions.md](cli-sessions.md) are rendered from report values, or from the call itself when
  it does not connect, and compared verbatim.

Adding a command means adding an argument struct with its `leaf!` spec to its grade's clap enum,
and a body that takes `Ctx<G>`. Everything else follows from the definition.

## Phase 0 results (build 168999)

The contract left the open Phase 0 questions to tunables, so an answer would change a value or a
behavior inside t32ctl, never the command line. The safe tier of `t32probe` has run against
PowerView build 168999, and the answers settled every tunable but the chunk sizes, which keep
their measured default. [trace32-pitfalls.md](trace32-pitfalls.md) has the evidence.

| Question | Build 168999 | What t32ctl does |
|---|---|---|
| `DO` over ExecuteCommand returns at once or at script end | At once (`script-lab`). | The runner polls the PRACTICE state; `tuning.do_blocks` is gone. |
| EXP global macro names with or without `&` | With `&`; a bare name is a separate store that no script sees (`macro-visibility`). | Every macro is set and read with `&`; `tuning.macro` is gone. |
| Which existence function answers | `OS.FILE.readable()` (`tempdir`). | Fixed; `tuning.exists` is gone. |
| How the stage root is named | Literally: commands sent over RCL never expand macros. | `<OS.PTD()>\t32ctl` or `[staging] root`, spelled out by the client; `tuning.stage_root` is gone. |
| Keepalive interval | About 2 s, below the 10 s idle budget (`keepalive`). | Fixed; `tuning.keepalive` is gone. |
| Chunk sizes | 15360 bytes per memory request, both directions (`vm-rw`). | `tuning.read_chunk` and `tuning.write_chunk`, default 15360: the only tunables left. |
| A `DIALOG.OK` window outlives `T32_Stop` | Not measured yet (`dialog`, opt-in). | A behavior: `dialog` is exit 5, and a later `no-answer` names a modal dialog. |
| `Go <loc>` leaves a temporary breakpoint | Not measured yet (`run-control`, opt-in). | `tuning.go_leaves_breakpoint`, planned with `run go`: `run go LOC` would use a tagged temporary breakpoint. |

Other results changed what the contract says:

| Result | Contract |
|---|---|
| Commands sent over RCL never expand macros, and a function's file argument is a name, not an expression. | `raw cmd` and `raw eval` send their text literally: `&name` stays literal, and a function takes a literal file name. |
| A command sent over RCL is at most 2037 characters. | `raw cmd` and `raw eval` text is 1 to 2037 bytes (`notation`). |
| A PRACTICE macro holds at most 4 KiB. | `raw script` arguments are at most 4 KiB in total. |
| A blocking command (`WAIT`) on the command line blocks every new RCL connection until it ends. | `raw cmd` with a blocking command holds the call and keeps every other RCL client out; long work belongs in `raw script`, where `WAIT` is fine. |
| `&x="0"` stores `0`, `&x=0` stores `0x0`, `&x=0.` stores `0.`. | Scripts assign `&t32ctl_rc="0"`; t32ctl takes `0`, `0.` and `0x0` as zero ([profiles.md](profiles.md#writing-procedure-scripts)). |
| `ENDDO` hands back unevaluated text; an undeclared macro stays literal in a script. | Results travel only through `&t32ctl_rc` and `&t32ctl_msg`, and t32ctl sets every macro a script may read. |
| `END` ends every script, closes every custom dialog and every `OPEN` file. | A residue notice that asks for `END` says so. |
| With the target down, `Register(PC)` fails with "target system down". | The header of a down target is `down`; reads that need the target are exit 3 `target-down`. |
| The `api.` function group starts at build 171257. | `read status` asks `RCL.TCP.NrUsedCons()` first, then `api.RCL.TCP.NrUsedCons()`. |

## What Phase 1 does not do

- Live variable watching and stop notifications (`watch`), trace, FDX, triage composites, and
  OS-aware thread lists. These are Phase 2 and later.
- Independent per-core run control (AMP): run control acts on all cores, as TRACE32 SMP mode does.
- One call spanning two PowerViews, or starting PowerView.
- Excluding callers in another WSL instance or on another host: the lease, the locks, and the
  epoch are WSL files. `read status` shows the RCL client count, so such callers are visible.
- Operator trust of board profiles. A procedure runs at the grade its profile declares, and the
  memory map is the profile as written ([ADR 0002](adr/0002-phase1-cli-contract.md)).
- A Windows-resident `.cmm` library. Everything a procedure runs travels in its bundle, except
  TRACE32 installation files under `~~/`, such as the eMMC algorithm.
- A waiting queue for the lease, a renew command, or an unbounded hold.
- A built-in flash command: flashing is a board procedure.
- Bypass flags of any kind, sticky core or frame selection, and an MCP server mode.
